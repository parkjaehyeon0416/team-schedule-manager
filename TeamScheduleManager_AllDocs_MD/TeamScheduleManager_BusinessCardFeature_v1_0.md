# 0. 문서 개요

이 문서는 Team Schedule Manager의 모바일 명함 기능 설계서입니다.

**명함은 단순한 자기소개 도구가 아니라 ****"****고객이 지인에게 추천할 때 전달하는 바이럴 도구****"****입니다.**

| **항목** | **내용** |
| --- | --- |
| **기능명** | 모바일 명함 + QR 공유 |
| **도입 시기** | 매뉴얼 v13 (견적서 PDF + 일정 연동과 함께) |
| **우선순위** | 로드맵 출시 전 필수 항목 (기존 12위 → 격상) |
| **핵심 가치** | 고객이 지인에게 명함 전달 → 자연 바이럴 → 마케팅 비용 0원 |
| **범위 (출시 시점)** | 명함 작성 / QR 공유 / 견적서·보고서 연동 / 조회수 카운트 |
| **범위 (출시 후 검증 대상)** | 앱 내 문의 시스템 / 안심번호 / 콜백 추적 / Pro 디자인 |

# 2. 핵심 설계 원칙

## 2-1. 원칙 ① 가볍게, 미니멀하게

명함 기능에 너무 많은 옵션을 넣으면 만들기도 어렵고 사용자도 안 채워요.

출시 시점엔 "최소한의 정보 + 시공 사진 + QR 공유"만 있으면 충분해요.

## 2-2. 원칙 ② 시공 사진 자동 연동

우리 앱에는 이미 시공 전·중·후 사진이 쌓여 있어요. 이걸 명함에 자동으로 표시해요.

**사용자가 따로 포트폴리오를 만들 필요 없이, 앱 사용만 해도 명함이 풍부해져요.**

## 2-3. 원칙 ③ 앱 설치 없이도 볼 수 있어야 함

명함 받은 사람이 앱 깔아야만 본다면 → 바이럴 효과 없음.

**웹 페이지 형태로 누구나 볼 수 있게 만들고, 페이지 하단에 앱 다운로드 유도.**

## 2-4. 원칙 ④ 워터마크는 자연스럽게

명함 페이지 하단에 "이 명함은 [앱이름]으로 만들어졌습니다 + 다운로드" 표시.

**지나치게 큰 광고는 명함의 신뢰도를 떨어뜨리니 작고 단정하게.**

# 5. DB 설계

## 5-1. business_cards 테이블

CREATE TABLE business_cards (

  id                  BIGINT PRIMARY KEY AUTO_INCREMENT,

  user_id             BIGINT NOT NULL UNIQUE COMMENT '사용자당 1개',

  share_code          VARCHAR(20) UNIQUE NOT NULL COMMENT 'URL용 짧은 코드',

  display_name        VARCHAR(100) COMMENT '표시명 (예: 김OO 기사)',

  job_title           VARCHAR(100) COMMENT '직함 (예: 도배 전문)',

  years_experience    INT NULL COMMENT '경력 년수',

  service_area        VARCHAR(100) COMMENT '활동 지역 (예: 서울/경기)',

  specialty           VARCHAR(255) COMMENT '전문 분야 (예: 합지·실크·천장)',

  tagline             VARCHAR(255) COMMENT '한 줄 소개',

  profile_photo_path  VARCHAR(500) NULL COMMENT '프로필 사진 경로',

  showcase_photo_ids  JSON NULL COMMENT '표시할 시공 사진 ID 배열',

  is_public           TINYINT(1) DEFAULT 1 COMMENT '공개 여부',

  view_count          INT DEFAULT 0 COMMENT '누적 조회수',

  monthly_view_count  INT DEFAULT 0 COMMENT '이번 달 조회수',

  last_viewed_at      TIMESTAMP NULL,

  created_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

  updated_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  deleted_at          TIMESTAMP NULL,

  INDEX idx_share_code (share_code),

  INDEX idx_user (user_id)

);

| **⚠️ 외래키 제약은 사용하지 않아요 (프로젝트 정책)** user_id는 unsignedBigInteger로만 처리, 무결성은 애플리케이션 레이어에서 보장 |
| --- |

## 5-2. card_views 테이블 (조회 로그)

명함 조회수 통계용 테이블이에요. 출시 시점엔 단순 카운트만 사용해요.

CREATE TABLE card_views (

  id                BIGINT PRIMARY KEY AUTO_INCREMENT,

  card_id           BIGINT NOT NULL,

  viewer_ip_hash    VARCHAR(64) NULL COMMENT '중복 방지용 (해시)',

  user_agent        VARCHAR(255) NULL,

  referrer          VARCHAR(255) NULL,

  viewed_at         TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

  INDEX idx_card_date (card_id, viewed_at DESC)

);

| **💡 같은 IP에서 짧은 시간 내 여러 번 조회하면 1회로만 카운트 (중복 방지).** 개인정보 보호를 위해 IP는 SHA-256 해시로 저장. |
| --- |

# 9. 매뉴얼 배치 — v13에 통합

명함 기능은 단순해서 별도 매뉴얼 만들 필요 없이 v13에 같이 작업해요.

견적서 PDF에 명함 QR이 들어가니까 함께 작업하는 게 효율적이에요.

| **순서** | **작업** | **상세** |
| --- | --- | --- |
| **1** | **DB 마이그레이션** | business_cards / card_views 테이블 생성 |
| **2** | **Laravel 모델** | BusinessCard, CardView 모델 + share_code 자동 생성 로직 |
| **3** | **API Controller** | BusinessCardController — CRUD + 공개 조회 (인증 불필요) |
| **4** | **웹 명함 페이지** | Blade 또는 정적 HTML — Open Graph 메타태그 포함 |
| **5** | **모바일 화면** | BusinessCardScreen / CardEditScreen / CardShareModal |
| **6** | **QR 코드 생성** | react-native-qrcode-svg 라이브러리 |
